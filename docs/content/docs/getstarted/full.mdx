This is a Docker-based setup which requires both Docker *and* Docker Compose. It allows you to run a full LibreCloud instance with all services configured as they should be.

<InfoBox type="warning">
LibreCloud is still in its early stages! Production doesn't mean it's ready for your business. Use at your own risk.
</InfoBox>

## 1. Install Dependencies

<Steps>
<Step>
### Docker

Docker is a containerization platform which we use to run LibreCloud.

```bash
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh
```
</Step>
<Step>
### Bun

Bun is a fast JavaScript runtime, which we prefer over `npm`. These instructions will be written for Bun, but could be adapted to `npm` or `yarn` if needed.

```bash
curl -fsSL https://bun.sh/install | bash
```
</Step>
</Steps>

### 2b. Configure Initial Environment Variables

Now, we will be working in the `web` directory. As we configure LibreCloud services, we will move between the root and individual service directories.

<Steps>
<Step>
#### Move to Web Directory

```bash
cd web
```
</Step>
<Step>
#### AUTH_SECRET

Execute the below command to generate a `.env.local` file with an `AUTH_SECRET`.

```bash
bunx auth secret
```
</Step>
<Step>
#### Altcha token

If you plan to use the signup forms, you will need to use Altcha, a private proof-of-work CAPTCHA. All you need to do is execute the script below, and it will be written to your `.env` or `.env.local`.

```bash
$ bun tools/hmac.ts
Successfully wrote ALTCHA_SECRETKEY to .env.local
```
</Step>
<Step>
You will now have a `.env.local` file in your `web` directory. Keep note of its location as we will be updating it frequently along this guide.

### 2c. Bring Up Nginx Proxy Manager

Shortly, you will need to configure Nginx Proxy Manager to route traffic to your new services, and LibreCloud itself. To do this, you will need to bring up Nginx Proxy Manager.

Run the following command to bring up Nginx Proxy Manager:

```bash
docker compose up -d nginx-pm
```

### 2d. Configure initial environment variables

Now, you should update your `.env.local` file (in `web/`) with your desired
configuration. Follow the next steps in order.

<Steps>
<Step>
#### AUTH_TRUST_HOST

If you're using a reverse proxy (e.g. Nginx Proxy Manager), add this line to your `.env.local` file:

```ini
AUTH_TRUST_HOST=true
```
</Step>
<Step>
#### NEXTAUTH_URL

Add this line to your `.env.local` file:

```ini
NEXTAUTH_URL=http://web.local
```

Replace `web.local` with your actual domain name.
This is where the LibreCloud homepage will be, and where clients access their account.

For example, we use `NEXTAUTH_URL=https://librecloud.cc` for our production instance.
</Step>
<Step>
#### Generic Variables

Now, you should read more about configuration on the [Environment Variables](/docs/reference/env) page, and set your desired environment variables.

For now, you should at least set the following variables before continuing:

- `NEXT_PUBLIC_SIGNUP_ENABLED`
- `NEXT_PUBLIC_DONATE_URL`
- `NEXT_PUBLIC_SUPPORT_EMAIL`
- `NEXT_PUBLIC_TELEGRAM_CHANNEL_URL`
- `NEXT_PUBLIC_TELEGRAM_GROUP_URL`

These variables should already be set in the example `.env.local` file from the last steps:

- `AUTH_SECRET`
- `ALTCHA_SECRETKEY`
</Step>
<Step>
#### Email 2FA

Now, you should configure email 2FA. Follow the [Email 2FA](/docs/guides/email-2fa) page from start-to-finish, then continue on.
</Step>
</Steps>

### 2e. Initialize Prisma

Because `web` uses a database for storing Git link statuses (and other things to come),
you will need to initialize the SQLite database.

However, if you are using Docker Compose, a database has already been generated in the container image and is blank.

If you have a reason to initialize Prisma now, feel free to execute:

```bash
bunx prisma migrate dev --name init
```

<Steps>

### 3c. Mailserver

Did you think we were done? Hah! It's time to configure your mailserver and `mail-connect`.

This is no easy task. It may decrease the time you spend touching grass by no more than 100%, which I am *not* responsible for!

Follow this "simple" process to prepare your mailserver:

<Steps>
<Step>
#### Prior Reading

You may want to read the [Introduction page for docker-mailserver](https://docker-mailserver.github.io/docker-mailserver/latest/introduction/) to learn more about mailservers and how `docker-mailserver` works.
</Step>
<Step>
#### PTR Record

Now, you will need to prepare your server for becoming a mailserver.

You should start by creating a PTR record, which your host should allow you to modify. This is normally done through a support ticket or your host's control panel.

A PTR record is a reverse DNS record that maps an IP address to a hostname. This is required to prevent your emails from being marked as spam.

Set the PTR to your desired mailserver hostname. For ease-of-deployment, you should use `mail.yourdomain.com`, but if you want to get creative, feel free to use `yourdomain.com`.
</Step>
<Step>
#### Ensure Email Ports are Open

Many hosts block access to email ports such as `25` and `587`. You will need to ensure these ports are open.

You can test this by running:

```bash
telnet smtp.gmail.com 25
```

If the connection times out or you get stuck on `Trying [ip address]...`, your host is blocking access to email ports.
</Step>
<Step>
#### DNS Configuration

You will have some DNS setup to do, which is documented on the [Usage page for docker-mailserver](https://docker-mailserver.github.io/docker-mailserver/latest/usage/#minimal-dns-setup).

You will need to set the following records:

- `MX` record
- `SPF` record
- `DKIM` record
- `DMARC` record
</Step>
<Step>
#### Deploying `docker-mailserver`

Now, we will part again so you can follow the latest documentation for docker-mailserver.

<InfoBox type="info">
It is suggested that you change the `docker-data` folder that docker-mailserver's default Compose file mounts to a better name. In our example, we will use `mailserver` as the name of this directory.
</InfoBox>

You can start from the [Deploying the Actual Image](https://docker-mailserver.github.io/docker-mailserver/latest/usage/#deploying-the-actual-image) section.

Ensure you take a look at the [Environment Variables](https://docker-mailserver.github.io/docker-mailserver/latest/config/environment/) page to setup docker-mailserver with your preferences.

<InfoBox type="tip">
You can keep the internal authentication, as `mail-connect` will help with managing accounts within `docker-mailserver`. LDAP setup is not needed at the moment.
</InfoBox>

After following the instructions, you should have a running mailserver.
</Step>
</Steps>

### 3d. `mail-connect`

We will now clone `mail-connect`, configure it, and deploy.

<Steps>
<Step>
#### Clone `mail-connect`

This command should be run in your `librecloud` directory (the root).

```bash
git clone https://github.com/ihatenodejs/mail-connect mail-connect
```
</Step>
<Step>
#### Copy Docker Compose File

We will now copy the example `docker-compose.yml` file.
This should be run from `librecloud`, and not inside the new `mail-connect` directory:

```bash
cp mail-connect/docker-compose.yml.example mail-connect/docker-compose.yml
```

</Step>
<Step>
#### Configure and Deploy `mail-connect`

You should now follow the steps in the [README](https://github.com/ihatenodejs/mail-connect/blob/main/README.md) to configure and deploy `mail-connect`.

You can step step one and step three's first `mv` command, which we've already done.

Ensure you comment out the `ports` section in `mail-connect/docker-compose.yml`, which should not be exposed in a production setup.
</Step>
<Step>
#### Configure LibreCloud with `mail-connect`

We will now configure LibreCloud with `mail-connect`.
Provided you kept the `mail-connect` service name, this example line will work for you.

Open `web/.env.local` and add the following line:

```ini
MAIL_CONNECT_API_URL=http://mail-connect:3000
```
</Step>
</Steps>

## 4. First Start and Finalizing Setup

Great work! We can now startup the LibreCloud web interface, and any other missing services.

<Steps>
<Step>

Execute the following from the root directory (`librecloud`):

docker compose up -d # Bring up any stragglers

You may customize the container with the included `docker-compose.yml` file if needed.
</Step>
<Step>

Click the "Add Proxy Host" button.

<Step>

Fill in the following fields:

- Domain Names: `librecloud.local` (replace with your desired LibreCloud (sub)domain name)
